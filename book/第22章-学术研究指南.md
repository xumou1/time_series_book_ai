# 第 22 章 · 学术界如何做时序研究：模块、改进点与认可标准（研究指南）

**本章目标**：学完本章后，你能①说出主流时序研究的"标准流水线"与简单/复杂研究的分层；②像看图纸一样读懂一篇论文"改了什么模块、作用是什么"；③列出评判指标的完整清单；④知道"在多少指标上赢才算被认可"的学术通行惯例。

> 定位说明：本书主体（第 1–21 章）教你"用"时间序列；本章是**面向想进入研究领域的读者**的扩展指南——把前面各章零散的"改良点—作用—评估"整理成一套可操作的学术研究框架。

---

## 22.1 动机：从"会用"到"会研究"

读完前 21 章，你已经能：用统计方法建模、用深度学习预测、用评估协议判断好坏。但如果你去读一篇时序论文，可能会困惑：*他们为什么要这样改？为什么这样的结果"算数"？*

答案藏在学术共同体的一套**隐性惯例**里：

> **研究 = 在标准流水线上，对一个模块做一处有动机的改进，并用公认的指标和基线证明这个改进真的有用。**

本章把这套惯例讲清楚：研究怎么做（22.2–22.3）、改什么（22.4）、拿什么评判（22.5–22.6）、怎么写（22.7）、别踩什么坑（22.8）。

## 22.2 主流研究范式：标准流水线与研究分层

### 22.2.1 标准流水线（几乎所有时序论文的骨架）

```
① 问题定义：预测什么（单/多变量）、多长（horizon）
② 方法设计：提出/改进一个模型（本章 22.3、22.4）
③ 实验：标准数据集 × 强基线 × 指标（22.5）→ 对比表
④ 消融：拆掉每个组件，证明"每个改动都有用"
⑤ 可视化/解释：注意力图、分解图、预测样例
⑥ 结论：在多少组合上赢了（22.6）
```

**为什么是这套流水线**：它让不同论文**可比**——同样的数据集、同样的指标、同样的基线，谁好谁坏一目了然。这也正是第 19 章"评估协议"在学术界的制度化版本。

### 22.2.2 简单 vs 复杂研究的分层

| 层级 | 典型研究对象 | 例子 | 难度 |
|---|---|---|---|
| **简单** | 单变量、单一数据、统计/轻量改进 | 某 GARCH 变体、某指数平滑的鲁棒版本 | 低（重统计功底） |
| **中等** | 单变量/多变量 + 一个深度模型改进 | 给 LSTM 加注意力、改损失函数 | 中 |
| **复杂** | 长序列、多变量、跨域、概率/生成式 | Transformer 变体、扩散预测、基础模型 | 高（重工程与算力） |

**要点**：**简单研究 ≠ 低价值**。统计方向的精细改进（如 GARCH 族的扩展）在金融计量顶刊（Journal of Econometrics 等）依然吃香；深度方向拼的是"在标准基准上全面胜出"。选择哪一层，取决于你的数学功底与算力资源。

### 22.2.3 标准基准数据集（深度研究的事实标准）

| 数据集 | 领域 | 特点 |
|---|---|---|
| **ETT**（电力变压器） | 能源 | 15 分钟采样，强日/周周期，深度学习基准之王 |
| **Weather** | 气象 | 21 个变量，非平稳强 |
| **Electricity** | 电力 | 321 个变量，多变量依赖 |
| **Traffic** | 交通 | 862 个传感器，强周期 |
| **ILI**（流感） | 医疗 | 周数据、短样本、突发性强 |

**预测长度（horizon）惯例**：96 / 192 / 336 / 720（ETT 等按 15 分钟=1 步；即 1~30 天）。**论文要在每个 horizon 上都报结果**——只报一个 horizon 会被审稿人质疑。

## 22.3 模块地图：时序模型的"积木"

第 15、17 章你已经见过这些模块。这里把它们**系统化成一张装配图**——任何时序模型都是这些积木的组合，论文的"改进"几乎总是替换/增强**其中一块**：

```
输入处理层        序列建模层         输出层
─────────        ─────────        ─────────
· 分片 patch      · 注意力变体       · 直接多步 / 自回归
· 通道策略        · MLP             · 点预测 vs 分布
  (独立/混合)     · 卷积/TCN        · 生成式（扩散）
· 归一化 RevIN    · RNN/LSTM        · 区间/分位数
· 嵌入            · 状态空间 Mamba
 (时间/频率)      · 线性层
                 · 结构先验：
                   分解(趋势/季节)
                   自相关/频域
──────────────────────────────────────────
训练层：损失函数(MSE/分位数/似然) · 掩码自监督/预训练 · 微调
```

**读懂一篇论文的速记法**：*"它改了哪个积木？为什么改（动机）？改完有什么效果（消融里哪一行提升了）？"* ——三问齐了，这篇论文你就读懂了。

---

## 22.4 改进点总览：改什么、作用是什么

| 改进对象（积木） | 作用（动机） | 代表工作 |
|---|---|---|
| **输入分片 patch** | 局部模式更稳、计算降为 1/P²、视野变长 | PatchTST |
| **稀疏/线性注意力** | 复杂度 O(L²)→O(L log L)，长序列可行 | Informer |
| **分解内嵌** | 显式建模趋势/季节（结构先验） | Autoformer、DLinear |
| **归一化（RevIN）** | 缓解非平稳、防泄漏（统计只用训练段） | RevIN |
| **通道交互策略** | 多变量关系建模 vs 防通道间干扰 | iTransformer、PatchTST |
| **输出分布化** | 从点预测升级为概率预测（区间/分位数） | DeepAR、Chronos |
| **预训练/掩码自监督** | 跨数据集表示学习、少样本 | PatchTST 预训练、基础模型 |
| **高效状态空间** | 近线性复杂度长程建模 | S-Mamba、TimeMachine |

**通用规律（背下来）**：*时序论文的改进要么是"更高效"（降复杂度/降参数），要么是"更准"（塞进结构先验/更好的表示），要么是"更全面"（概率输出/多任务）*。一篇论文通常只占其一，别贪多。

## 22.5 评判指标：完整清单

### 22.5.1 点预测指标

| 指标 | 含义 | 备注 |
|---|---|---|
| **MSE** | 平方误差均值 | 惩罚大误差，最常用 |
| **MAE** | 绝对误差均值 | 直观，对离群点稳健 |
| **RMSE** | MSE 开根号 | 与数据同单位 |
| **MAPE / SMAPE** | 百分比误差 | 注意：真实值为 0 时失效 |
| **MASE** | 相对朴素基线的误差 | 跨数据集可比（第 19 章） |

### 22.5.2 概率预测指标（做了分布输出就必报）

- **CRPS**：分布与真值的吻合度（越低越好，第 16 章）；
- **Quantile Loss / Pinball Loss**：分位数损失；
- **区间覆盖率**：90% 区间应盖住约 90% 真值（第 16、19 章）。

### 22.5.3 效率指标（顶会越来越看重）

- 参数量（Params）、FLOPs、训练/推理时间、显存。

### 22.5.4 报告惯例（重要）

```
每个数据集 × 每个 horizon（96/192/336/720）→ 一张对比表
多次运行 → 报 均值 ± 标准差（不是单次最好）
全部指标都要报，不能只报对自己有利的那个
```

## 22.6 "在多少指标上赢才算被认可"：学术通行惯例

这是你直接问的问题。**没有官方硬性数字**，但学术共同体（尤其机器学习顶会）有相当一致的隐性标准：

**核心标准：在"大多数"基准组合上全面胜出，且消融支持设计动机。**

具体拆解（通行惯例，非规则）：

1. **覆盖面**：通常 3~5 个数据集（跨领域：能源/气象/交通…），每个数据集报 **4 个 horizon**（96/192/336/720）——即 12~20 个"数据集×horizon"组合。
2. **胜出比例**：**一般要求在 ≥ 2/3（约三分之二）以上的组合上取得最优（SOTA）或与最优并列**。只在 1~2 个数据集上赢，通常不被认可（会被审稿人认为是"挑数据"）。
3. **必须是"显著"**：多次运行（≥3 次）报均值±标准差；两方法差距小于标准差时不算赢。**可加 Diebold–Mariano 检验**（两预测误差差异的显著性检验，时序预测的"显著性检验"标准工具）。
4. **消融必须成立**：去掉你加的每个组件，性能应下降——**这是"改进有效"的因果证据**，比"赢了几个指标"更重要。
5. **基线必须够强**：不能只对比老模型——要对比当时的最新 SOTA + 统计基线（ETS/ARIMA/线性）。第 15 章的线性之争已经把"不跑线性基线"变成审稿红线。
6. **同计算预算**：对比时模型规模/训练成本要公平，否则会被质疑"用算力换精度"。

**一句话回答你的问题**：*通常在 12~20 个"数据集×horizon"组合里赢下三分之二以上、且消融和强基线都过关，改进才会被学术共同体认可。* ——注意，**"赢了"指的是显著优于，不是小数点后第三位的侥幸。**

## 22.7 一篇标准论文的结构（示例骨架）

以"提出某个新模块 M 改进预测"为例：

```
摘要：一句话痛点 + 方法名 + 三个数字（赢了几个数据集、降了多少误差）
1 引言：为什么现有方法不够（如"注意力无视季节结构"）
2 相关工作：与 3~5 篇最近工作区分（强调你的动机不同）
3 方法：模型图 + 每个组件公式 + 每个组件的动机（一段一动机）
4 实验：
  4.1 设置：数据集、horizon、基线列表、实现细节（种子/算力）
  4.2 主结果：对比表（均值±标准差，赢的加粗）
  4.3 消融：拆模块 → 证明每块有用
  4.4 效率：参数/时间对比
  4.5 可视化：预测样例、注意力/分解图
5 结论：两句话（做了什么 + 效果），别再自吹
```

**审稿人最先看的三处**：主结果表（赢面够不够）、消融（动机是否兑现）、基线列表（有没有偷懒）。——这三处全过，论文基本就立住了。

## 22.8 学术研究常见陷阱（与本书前面呼应）

1. **选择性报告**：只报赢的数据集/horizon——**审稿人查全表，报全才有说服力**。
2. **弱基线对比**：用 2020 年的模型当基线，显得自己强——**基线用当时 SOTA**（第 15 章教训）。
3. **不做消融**：不知道赢在哪个组件——**消融是"改进有效"的唯一因果证据**。
4. **归一化/预处理泄漏**：全序列归一化、特征时点越界——**第 13、19 章的铁律在论文里同样致命**。
5. **单次运行报最优**：换种子成绩飘忽——**报均值±标准差（≥3 次）**。
6. **不报效率**：模型大 10 倍只赢 1%——**报参数/时间，让读者判断值不值**。
7. **"创新"拼贴而非改进**：堆砌多个已有模块，无清晰动机——**每个组件都要回答"为什么改"**。

## 22.9 相似问题与已有解决方案：历史回响

| 本环节的困难 | 谁遇到过 | 如何解决 | 本书对应 |
|---|---|---|---|
| "改进到底有没有用" | 第 15 章线性之争 | 消融 + 强基线 + 全面报告 | 第 15、19 章 |
| "区间/概率预测怎么评" | 概率预测文献 | CRPS + 覆盖率（第 16、19 章） | 第 16、19 章 |
| "两模型差异是否显著" | 预测评估（Diebold & Mariano 1995） | **DM 检验**：误差差的显著性检验 | 本章；第 19 章 |
| "跨数据集怎么比" | M4/M5 竞赛 | MASE（朴素基线归一化） | 第 6 章 |
| "基线的地位" | Makridakis 竞赛、LTSF-Linear | 统计/线性基线成为标配 | 第 6、15 章 |

**核心启示**：学术认可的本质是**可复现的全面优势**——不是"我赢了"，而是"我在公认的台面上、用公认的尺子、赢过了公认的对手，并且能解释为什么赢"。

## 22.10 本章小结

1. **研究 = 标准流水线 + 一处有动机的模块改进 + 公认指标/基线证明**。
2. **模块地图**：输入处理/序列建模/结构先验/输出/训练五大积木——论文的改进几乎总是替换其中一块。
3. **指标**：点预测（MSE/MAE/MASE…）+ 概率（CRPS/覆盖率）+ 效率（参数/时间），全报。
4. **认可惯例**：在 12~20 个"数据集×horizon"组合中**赢下 ≥2/3 且显著**，消融成立、强基线过关——改进才算数。
5. 陷阱：选择性报告、弱基线、无消融、泄漏——全是本书前面讲过的"评估纪律"的学术版。

## 22.11 练习与自测

1. ★ 标准流水线的六个环节是什么？（提示：22.2.1）
2. ★ 一篇深度时序论文通常报几个数据集、几个 horizon？（提示：22.2.3/22.6）
3. ★★ 为什么"消融"比"赢了多少指标"更重要？（提示：22.6 第 4 条）
4. ★★ 两个模型 MSE 相差 0.5%，一个跑 3 次标准差 2%，另一个 1%——能说前者赢了吗？（提示：22.6 第 3 条）
5. ★★★ 挑一篇近期时序论文（如 iTransformer 或 PatchTST 原论文），填写"模块三问"：①它改了哪个积木？②为什么改（动机）？③消融里哪一行证明了它有用？（提示：22.3 速记法）

**简答提示**：1 问题定义→方法设计→实验→消融→可视化→结论；2 3~5 个数据集、4 个 horizon（96/192/336/720）；3 消融证明"赢来自你的改进而不是模型体积/运气"——是因果证据；4 不能——0.5% 远小于标准差 1~2%，差异不显著；5 如 PatchTST：改了输入积木（patch）→ 动机是局部模式+降计算 → 消融中"去 patch 退化为单点输入"行性能下降。
