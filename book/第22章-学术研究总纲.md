# 第 22 章 · 学术研究总纲：应用研究与方法改进的两大范式

**本章目标**：学完本章后，你能①清楚区分"时间序列模型的应用"与"模型本身的改进"两种研究范式，说出各自的追求与评判标准；②掌握两种范式共享的研究流水线、指标与认可标准；③判断自己当前该走哪条路（或如何结合）。

> 定位说明：这是"研究指南"部分的总纲。**第 23 章**详细展开"应用研究该注重什么"，**第 24 章**详细展开"方法改进的模块体系与当前学界正在改进的热点"。本章先给你一张地图。

---

## 22.1 动机：两种研究，两套玩法

翻几篇时间序列论文，你会发现它们其实分属**两种很不一样的研究**：

- 一篇讲"用 LSTM 预测某省电网负荷，比原厂方案省 12% 电费"——这是**应用研究**；
- 一篇讲"提出注意力分解模块 M，在 5 个公开基准上全面超越 SOTA"——这是**方法改进**。

它们的目标、评审标准、甚至"什么算成果"都不同。**很多人做研究失败，不是因为能力，而是拿错了范式**：做应用却按方法论文的标准要求自己（被批"没有创新"），或做方法却按应用标准（被批"没有实际价值"）。

> 一句话：**应用研究回答"这把螺丝刀在哪个活儿上好用、怎么用"；方法改进回答"怎么造一把更好的螺丝刀"。** 本章先把这两条路讲清楚，再给它们共享的"公共底座"。

---

## 22.2 两大范式总览

| 维度 | **应用研究（Application）** | **方法改进（Method Development）** |
|---|---|---|
| 起点 | 一个真实的领域问题（电力、医疗、金融…） | 一个公认的方法缺陷/未满足的能力 |
| 核心问题 | "这个任务该怎么建模？什么方法最适合？" | "怎么改进模块/机制，让它更准/更快/更全面？" |
| 产出 | 领域方案 + 洞见（哪种方法在该场景有效、为什么） | 新模块/新架构 + 公开基准上的评测 |
| 主要评判 | 是否解决真实问题、是否胜过**领域现有方案** | 是否在**标准基准**上全面胜出、消融是否成立 |
| 数据 | 领域真实数据（常不公开、有噪声/缺失/隐私） | 公开标准基准（ETT/Weather/Electricity…） |
| 风险 | 领域知识不足 → 方案脱离实际 | 改进无实质增量 → 只是"刷点" |
| 发表去向 | 领域期刊（能源、医学、金融信息学） | 机器学习/数据挖掘会议（NeurIPS/ICML/KDD/ICLR/AAAI） |

**判断自己该做哪种（三问）**：
1. 你手头有**真实的领域问题与数据**吗？有 → 应用研究是自然起点；
2. 你对**某个方法的缺陷**有深入理解、且有算力/代码功底吗？有 → 方法改进；
3. 两者都有？**先做应用发现问题，再抽象成方法改进**——这是最扎实的路线（见 22.6）。

---

## 22.3 公共底座：研究流水线（两种范式共享）

无论哪种范式，论文骨架相同：

```
① 问题定义 → ② 方法/方案设计 → ③ 实验（数据集×基线×指标）
→ ④ 消融/对照分析 → ⑤ 可视化与解释 → ⑥ 结论
```

- 应用研究：②是"方法选择与适配"，④是"与领域现有方案对照"；
- 方法改进：②是"新模块设计"，④是"拆模块消融"。

两种范式都逃不掉第 19 章的评估纪律：时间切分、防泄漏、强基线、多次运行报均值±标准差。

---

## 22.4 评判指标（公共清单）

| 类型 | 指标 | 适用 |
|---|---|---|
| 点预测 | MSE、MAE、RMSE、MAPE/SMAPE、MASE | 两种范式通用 |
| 概率预测 | CRPS、Quantile Loss、区间覆盖率 | 做了分布输出必报 |
| 分类/异常 | F1、AUC、精确率/召回率 | 任务涉及分类时 |
| 效率 | 参数量、FLOPs、训练/推理时间 | 方法改进必报，应用加分 |
| 领域专属 | 误报成本、决策收益、电费节省、回撤等 | **应用研究的关键指标**（见第 23 章） |

报告惯例：**每个数据集 × 每个 horizon（96/192/336/720）× 全部指标，多次运行报均值±标准差**。

---

## 22.5 认可标准：两种范式各有侧重

### 方法改进的认可（机器学习顶会通行惯例）

- 在 **12~20 个"数据集×horizon"组合**（3~5 个跨领域数据集 × 4 个 horizon）中**赢下 ≥2/3 且显著**（多次运行标准差之外的真实差距，可加 Diebold–Mariano 检验）；
- **消融成立**：去掉每个新组件性能下降——这是"改进有效"的因果证据；
- **基线够强**：当时 SOTA + 统计基线（ETS/ARIMA/线性），同计算预算对比；
- 不做消融、不报效率、只挑赢的数据集报 → 通常被拒。

### 应用研究的认可（领域期刊/场景惯例）

- **解决了真实问题**：不是"我们试了 5 个模型"，而是"我们为某问题建立了可用的方案"；
- **胜过来领域现有方案**（现有生产系统、专家规则、领域常用方法），而不只是胜过来自 ML 基准的模型；
- **指标贴合业务**：用领域指标（误报率、收益、成本），而不是只报 MSE；
- **可复现 + 领域专家认可**：数据/代码公开（或可说明），结论被领域同行认为合理。

> 一句话对比：**方法改进认"全面且显著的胜出 + 消融"；应用研究认"真实问题的可信解 + 胜过领域现状"。** 用错标准是新手最常见的失分点。

---

## 22.6 如何选择与结合：应用驱动方法改进

最扎实的研究路线往往不是二选一，而是**循环**：

```
领域问题（应用）→ 发现现有方法不适配 → 抽象出方法缺陷 → 提出改进（方法）
→ 回到领域验证改进确实有用（应用闭环）
```

**经典案例**：
- M4 预测竞赛（应用场景：混合频率真实数据）暴露"深度模型在单序列上不行" → 催生 N-BEATS（方法改进：纯 MLP 基展开）；
- 金融波动率建模（应用）暴露"方差恒定假设失效" → 催生 ARCH/GARCH（方法改进，诺贝尔经济学奖 2003）；
- 长序列预测基准（应用）暴露"注意力算不动/不顺序" → 催生 Informer/PatchTST 等（方法改进）。

**给入门者的建议**：先选一个**你懂业务的领域**做应用研究（问题驱动、数据可得、领域基线清楚），在过程中记录"方法不够用的时刻"——那就是你下一项方法改进的选题。**应用是你发现问题的窗口，方法是你解决问题的杠杆。**

## 22.7 本章小结

1. **两大范式**：应用研究（把方法用对地方）vs 方法改进（造更好的方法）——目标、评判、发表去向都不同。
2. **公共底座**：同一套流水线与评估纪律（第 19 章）。
3. **认可标准不同**：方法改进认"≥2/3 组合显著胜出+消融+强基线"；应用研究认"解决真问题+胜过领域现状+业务指标"。
4. **最佳路线**：应用驱动、方法落地——先做应用发现问题，再抽象成方法改进。
5. 接下来的两章：**第 23 章（应用该注重什么）** 与 **第 24 章（方法改进的模块与当前热点）**。

3. ★★ 你手头有一个"预测门店销量"的任务，但只有统计基线对比——按哪种范式评判它？缺什么？（提示：22.5 应用认可标准）
4. ★★ 为什么"只挑赢的数据集报结果"在方法改进里是致命的？（提示：22.5 与第 19 章）
5. ★★★ 找一篇应用型时序论文和一篇方法型时序论文各一篇，分别用 22.5 的两套标准评价它们"是否合格"。（提示：应用看领域基线/业务指标，方法看覆盖面/消融）

**简答提示**：1 前者解决真实领域问题（评判=胜过领域现状），后者改进模型本身（评判=基准全面胜出+消融）；2 全面显著胜出（≥2/3 组合）+ 消融成立 + 强基线与同预算；3 按应用范式，还缺"胜过领域现有方案（如店长人工规则/现用系统）"与"业务指标（备货成本/缺货率）"；4 选择性报告等于把测试集当训练集挑结果（第 19 章），审稿人查全表即穿帮；5 略。
